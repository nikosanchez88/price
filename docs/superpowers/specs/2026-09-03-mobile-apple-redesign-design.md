# 移动端 Apple 风格界面重塑设计

日期：2026-09-03  
状态：已完成交互式设计确认，待用户审阅书面规格

## 背景

跨境定价助手主要在手机上使用。用户的核心路径是输入综合汇率与出厂价，快速比较完整毛利阶梯并复制 CLP 售价；反推毛利使用频率较低。现有页面功能正确，但输入区纵向占用较多，表格信息层级偏弱，复制触控区域较小，深色反推卡片会抢占主流程注意力。

## 目标

- 在 320–440 px 宽度的手机上优先优化单手操作和数字比较效率。
- 采用克制的 Apple 系统视觉语言：分组背景、白色内容层、系统字体、系统蓝交互色和清晰层级。
- 让“输入 → 查看完整毛利阶梯 → 复制价格”成为页面主路径。
- 保留所有现有计算、验证、离线和安装能力。
- 将反推毛利降为默认折叠的次要功能，但不减少其能力。

## 非目标

- 不修改毛利、汇率、取整或反推公式。
- 不增加 IVA、平台佣金、运费、关税等独立输入项。
- 不增加历史记录、自定义毛利档位或云同步。
- 本轮不实现深色模式；颜色变量应为未来适配保留清晰语义。
- 不引入 UI 框架、图标库、字体 CDN 或其他运行时依赖。

## 设计原则

1. **数字优先**：CLP 售价是视觉焦点，RMB 是辅助信息。
2. **颜色有语义**：系统蓝只表示交互，绿色只表示成功，红色只表示错误；入库价本身不是警告。
3. **整页自然滚动**：不在页面中嵌套一个独立滚动表格，降低手机操作负担。
4. **渐进呈现**：主流程始终可见，低频反推功能默认折叠。
5. **触控友好**：主要触控目标不小于 44 px，并提供明确的按下、成功和失败反馈。
6. **无障碍优先**：不只依赖颜色表达状态，支持键盘、屏幕阅读器、缩放和减少动态效果。

Apple Human Interface Guidelines 建议在分组列表中使用分层的系统背景，并让颜色持续表达明确的交互或状态语义：

- https://developer.apple.com/design/human-interface-guidelines/color
- https://developer.apple.com/design/human-interface-guidelines/typography

## 信息架构

页面按以下顺序组织：

1. 紧凑页头：仅保留“定价”主标题，不使用占空间的英文眉题与说明副标题。
2. 输入卡片：币种分段控件在上，综合汇率和出厂价在同一行；极窄屏幕仍保证输入可读。
3. 当前成本摘要：显示“出厂价 × 综合汇率”和入库价；进入毛利阶梯后保持粘性，方便长列表滚动时保留上下文。
4. 毛利阶梯：完整显示入库价以及 20%、30%、40%、45%、50%、55%、60%、70%、80%、90% 档位。
5. 反推毛利：位于阶梯之后，默认折叠，点击后在当前页面内展开。
6. 轻量页脚。

## 视觉系统

### 颜色

采用已确认的“Apple 系统蓝”方向：

- 页面分组背景：接近 iOS `systemGroupedBackground` 的 `#F2F2F7`。
- 主内容层：白色。
- 主文字：接近 `#1C1C1E`。
- 次要文字：接近 `#6E6E73`。
- 分隔线：低对比度系统灰。
- 交互与焦点：系统蓝 `#007AFF`，必要时使用更深色文本变体保证对比度。
- 成功：系统绿，只用于复制成功。
- 错误：系统红，只用于验证和复制失败。

所有颜色通过语义化 CSS 自定义属性管理，避免在组件规则中散落硬编码。

### 字体与层级

- 使用系统字体栈，不加载外部字体。
- 页面标题使用大号粗体和紧凑字距。
- CLP 售价使用更强字重和等宽数字特性。
- RMB 放在 CLP 下方作为小号辅助文字，不删除该信息。
- 避免过细字重；输入字号至少 16 px，防止 iOS 聚焦时自动缩放。

### 表面与留白

- 卡片使用 16–20 px 圆角、轻边框和极轻阴影。
- 不依赖大面积玻璃拟态；模糊仅用于粘性摘要或浮层。
- 将现有红色入库价行改为中性分组行。
- 将现有深色反推卡片改为同体系的白色折叠卡片。

## 组件与交互

### 输入区域

- RMB/CLP 使用 iOS 风格分段控件，并继续维护 `aria-pressed`。
- 综合汇率与出厂价保持实时计算，不增加提交按钮。
- 原有正数校验、汇率本地保存和清空行为不变。
- 输入错误显示在对应字段附近，错误文本和边框同时表达状态。

### 当前成本摘要

- 输入有效时显示当前出厂价、综合汇率和入库价。
- 摘要在毛利阶梯顶部形成轻量粘性上下文；滚动后不遮挡列表内容或安全区域。
- 输入无效或为空时不显示伪造结果。

### 毛利阶梯

- 使用垂直分组列表替代横向表格视觉。
- 入库价为不可复制的中性首行。
- 每个毛利档位为一个语义化按钮：左侧显示毛利率，右侧以 CLP 为主、RMB 为辅助，并保留复制图标。
- 点击行内任意位置复制 CLP 售价；键盘 Enter/Space 同样可用。
- 可访问名称包含毛利率、CLP、RMB 和复制动作。
- 页面完整自然滚动到 90%，不使用嵌套滚动容器。

### 复制反馈

- 成功后该行短暂使用浅蓝背景，复制图标变为勾号。
- 页面底部显示轻量、自动消失的“已复制 … CLP”提示，并通过 `aria-live="polite"` 宣告。
- 复制失败时不显示成功状态；给出可读错误并提示手动复制。
- `prefers-reduced-motion: reduce` 下取消非必要动画。

### 反推毛利

- 使用可访问的折叠/展开组件，默认折叠。
- 标题说明为“反推毛利”，辅助说明为“店铺售价 / 网点实收价”。
- 展开后显示 CLP 输入、预估毛利率和 RMB 毛利。
- 保留当前低/中/高毛利的语义反馈，但不只依靠文字颜色区分。
- 结果说明继续强调这是简化预估，不是包含全部经营费用的净利润。

## 响应式行为

- 以 390 px iPhone 宽度为主要设计基准。
- 320 px 下不出现横向滚动、文字截断或小于 44 px 的核心触控目标。
- 430–440 px 下适当增加留白，但保持单列结构。
- 桌面端居中显示为窄幅工具，不扩展成多栏仪表盘。
- 处理 `safe-area-inset-top` 和 `safe-area-inset-bottom`，避免 PWA 全屏模式遮挡内容。

## 技术边界

- `calculator.js` 的公式和公开函数保持不变。
- `index.html` 重组语义结构并提供折叠区、成本摘要和列表挂载点。
- `style.css` 重建语义化颜色、间距、列表、粘性摘要和反馈状态。
- `script.js` 调整 DOM 渲染：生成可点击价格行、维护折叠与复制反馈，并保持现有验证和持久化逻辑。
- `sw.js` 在静态资源结构发生变化时更新缓存版本，保证安装版获取新界面。
- `README.md` 更新移动端使用说明与交互描述。

## 测试与验收

### 自动测试

- 现有公式单元测试必须全部保持通过。
- 浏览器测试验证上方输入仍为出厂价、列表首行为入库价、毛利档位完整到 90%。
- 验证点击整行和键盘均可触发复制，成功与失败反馈真实一致。
- 验证反推毛利默认折叠、可展开，计算结果不变。
- 验证有效输入显示成本摘要，无效输入清除旧结果。
- 验证 320、390 和 430 px 宽度没有页面横向溢出。
- 保留离线 PWA 和 axe WCAG A/AA 检查。

### 视觉验收

- 分别截图检查 320、390 和 430 px 的顶部、毛利列表中部与页面底部。
- 检查长数字、输入错误、复制成功、复制失败和反推展开状态。
- 检查触控焦点、键盘焦点以及减少动态效果偏好。

## 成功标准

- 用户在手机上无需横向滚动即可完成主要定价流程。
- 所有毛利档位均可自然下滑查看，并能整行点按复制。
- CLP 层级明显高于 RMB，但 RMB 信息仍可见。
- 页面视觉统一、颜色克制，反推区域不再压过主流程。
- 计算结果、验证、离线能力和无障碍测试不发生回退。
